## Trabajo 1 — Error al guardar una publicación con archivo

**Commit:** `(pendiente)`

### Problema

Al crear una publicación en `/admin/publications` **con archivo**, el guardado
fallaba con:

```
SQLSTATE[22001]: String data, right truncated: 1406 Data too long for column 'file' at row 1
```

Sin archivo se guardaba bien. Desde que los archivos se suben a S3, `handleFile()`
guarda en `file` un JSON con `download_link` (path en S3) y `original_name`, y eso
pasa fácil los 255 caracteres de la columna `varchar(255)`. Sin archivo solo guarda
`'[]'`, por eso no fallaba.

### Archivos modificados

| Archivo | Cambio |
|---|---|
| `database/migrations/2026_10_08_000000_change_file_column_on_publications_table.php` | nueva migración: `publications.file` pasa de `VARCHAR(255)` a `TEXT NULL` |

### Solución

Se amplió la columna a `TEXT` con un `ALTER TABLE ... MODIFY` directo, para no
depender de `doctrine/dbal` (Laravel 10 lo necesita para `->change()`). El
`down()` la devuelve a `VARCHAR(255)`. El controlador
(`app/Http/Controllers/Admin/PublicationController.php`) no cambia.

**Antes:**
```
$table->string('file')->nullable();   // VARCHAR(255)
```

**Después:**
```
ALTER TABLE publications MODIFY `file` TEXT NULL
```
